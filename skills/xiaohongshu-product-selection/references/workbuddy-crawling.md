# 腾讯 WorkBuddy 自动取证

## 实际取数路线

先查看当前会话真实可用的工具说明。已有对应平台连接器能直接读字段时可用它；否则使用 WorkBuddy 内置的网页读取能力。本机 WorkBuddy 5.8.3 实测工具名为 `WebFetch`，界面显示“网页获取”；其他版本以实际暴露名称/参数为准，不能编造调用。

公开商品链接读取没有已证实的“必须先打开 Chrome/Safari、安装某浏览器扩展或开通小红书 API”前置条件。不要把这些当成通用解决办法。需要登录态的站内对标搜索与公开商品页读取是两条能力路径，分别核验。

1. 从分享文案提取用户给出的原始完整 URL，原样交给网页工具并允许正常跳转。不要先删参数或用猜测的商品 ID 重建访问链接；展示/存档时才隐藏访问参数。
2. 第一次读取一次提取全部公开字段：商品名、已选规格、当前售价及促销条件、单品累计销量、店铺名、来源和时间。商品页“已售”与店铺区域“已售”分开保存。
3. 24h 加购在电脑端不可取得是预期边界。未读到时记 `null / unavailable_on_desktop`，到此停止加购自动读取；不因此第二次抓页面、换浏览器、建议安装接口或询问商家后台。
4. 名称、售价、单品累计销量中有缺失/冲突才补证一次：让已有工具返回目标区域原文/截图或使用当前已授权的渲染能力。第二次仍是缓存或同一摘要，不算重新核实；不靠换 prompt 宣称“再查也没有”。
5. 同一商品最多两次页面读取（跨工具合计）。首次环境失败只允许一次低成本确认；仍失败记录具体状态并止损。不为一个字段安装浏览器、下载运行时、修改代理或调试环境，不再追加 curl/解析短链。未取得最终 URL 时保留原分享 URL 即可，不猜最终 URL。

## 价格与销量的证据

网页转成纯文字可能丢失划线、颜色与换行。`到手价¥88.8` 等拼接文本不一定表示 88.8 是当前售价；不能仅因出现两个价格就认定价格冲突，也不能总把较小值当售价。

- **已核模板优先用脚本解析**：WorkBuddy WebFetch 的商品开头若形如 `**标题**: 商品详情/小红书 → ¥ → X → 到手价/券后价¥Y → 已售Z`，2026-10-21已对五个商品的网页视觉/DOM核对：X属于 `.price` 主售价，标签属于 `.price-in-hands_text`，Y属于 `.del-price` 划线参考价，Z属于 `.spu-text` 单品销量。标签修饰X，不修饰Y。这条规则只用于该完整模板；不是一律取较小值。
- 将实际工具返回的**完整原文**及原分享链接作为 JSON 从标准输入交给 `scripts/parse_price_block.py`（字段 `text, source_url`），读取输出。它只解析现有文本，无网络请求，不消耗二次抓取次数。`matched=true` 时复用 `sale_price` 为页面展示价、`price_label`为价格条件标签；`reference_price`按已核模板识别为参考价。保留额外优惠文案，不自行解释某张券就是该价唯一成因，也不把页面展示价保证为最终实付价。
- `matched=false`、脚本不可用或模板变更时回到下面的证据规则；不能照抄示例数值、为此安装运行时或把未匹配认作网站没价格。已识别模板时不要仅因同时出现X和Y而再次抓取。
- 优先采用同一规格下有明确语义的当前售价，或已有页面截图/DOM 中非划线售价；参考价/划线价另存，促销条件原样保留。
- 若只有扁平文本，主价格区金额与“已选”规格内明确的促销售价一致，且页面明确的立减金额也吻合，可记录为“页面展示促销价（附条件）”，保留这几处原文。不推断未显示的颜色/划线，也不保证到结算时仍满足限额优惠。
- 真实案例（2026-10-21）：工具原文含主价 29.8、“到手价¥88.8”、“限时立减59”、已选规格“前1000单29.8r”；这几处共同支持页面展示促销价29.8及其条件，88.8是否划线需视觉/DOM确认。这是取证范例，禁止把29.8等数字填入其他商品。
- 不满足上述证据时仅保留候选价格为 `unverified`，有剩余读取预算则补证一次；仍不明才请用户给当前商品价格区域截图。
- 单品销量取商品价格/标题区域的“已售”，店铺粉丝附近的店铺“已售”另存且不用于评分。只有店铺数字时单品销量保持未知。约数如“1.2万+”保留原文，不转成精确12000评分。
- 只有实际读取了目标区域，才说该区域未展示；工具错误、登录墙、空白壳页面、摘要遗漏均只能说“本次工具未取得”。

## 小红书笔记与对标搜索

用户发笔记链接时先读取笔记详情和关联商品。若存在可访问的关联商品链接，进入商品判断；否则请用户补充商品链接。

对商品进行对标取证时，使用当前已授权的小红书搜索能力搜索同款带货笔记：

1. 用商品名、核心型号/规格和可识别的同款特征搜索；
2. 只保留能够核实为同一商品的笔记；相似品不得标记为同款；
3. 对每条候选笔记分别读取笔记 URL、作者粉丝数、发布时间、点赞数、关联商品及抓取时间；
4. 将发布时间换算成 `days_ago` 时保留原始发布时间；
5. 优先覆盖最近 30 天，并允许检查至 90 天；
6. 每条笔记作为独立证据对象，禁止跨笔记拼接粉丝与发布时间；
7. 搜索到足以完成决策的有效低粉对标后可以停止；若未找到，应完成合理的关键词变体和 90 天范围检查后，才能报告“当前未找到”。

“未找到”必须说明搜索范围和抓取时间，不能等同于绝对不存在。

## 采购数据

不要从 1688/阿里巴巴网页尝试抓取采购数据。进入利润步骤后，直接按顺序向用户询问：

1. 准备采用的单件拿货价；
2. 采购端单件运费。

小红书销售价若已从商品页可靠读取，可直接复用；否则先询问用户准备售价。拿货价必须是符合实际采购数量或一件代发条件的价格，不能使用大批量最低阶梯价。用户给出货源链接但没有明确数字时，仍应请用户直接确认拿货价和单件运费，不打开网页反复尝试。

## 素材源

使用已抓取的同款笔记、商品主图/视频及其他可访问平台证据判断素材执行难度。输出证据数量和来源类型，再给 A/B/C：

- A：多来源存在足够图片/视频和可参考内容，前期不依赖实拍；
- B：素材有限但可通过混剪、AI 生图或二创完成测试；
- C：可靠素材不足或主要依赖真人实拍/复杂搭景。

只判断“素材是否可用于前期执行”，不自动断言版权可用。证据不足时标记 `unverified` 并追问，不凭商品类型猜测。

## 单一证据状态

每个商品只维护一份状态，报告、追问、脚本输入均从中读取；不另造一套数字。字段至少包含：

```json
{
  "input_url": "用户原始完整链接，仅在受限任务中保留",
  "display_url": "可公开展示的来源链接",
  "fields": {
    "sales_total": {"value": null, "raw": null, "status": "unverified", "tool": null, "source_url": null, "captured_at": null},
    "cart_24h": {"value": null, "raw": null, "status": "unavailable_on_desktop", "tool": null, "source_url": null, "captured_at": null}
  },
  "page_reads": 0,
  "cached_response": false
}
```

其他字段沿用相同结构；用户提供的值标 `user_provided`，自动明确证据标 `verified`。采集时间只表示有记录的实际读取时间，工具未提供时间则记未知；脚本 `parsed_at` 只是处理时间，不能冒充抓取时间。缓存响应不能冒充数据更新时间，不自行编造时间段。工具未给出最终地址时保持未知；不能为了填满表而猜 URL、规格或数字。送入评分脚本的值必须已验证或由用户明确提供，缺项继续为 null；业务阈值以 `config/thresholds.json` 为唯一来源。

## 未取得数据时怎么排查

排查只报告观察到的情况：

| 观察到的结果 | 下一步 |
|---|---|
| 没有网页读取工具/工具未启用 | 说明缺哪项宿主能力，请在 WorkBuddy 检查该能力；不虚构某个必装浏览器插件 |
| 真实返回未登录/未授权 | 说明是哪个工具/网站的授权；只能在该工具实际使用的会话中登录，外部浏览器登录不自动等于工具已登录 |
| 验证码/访问受限 | 停止自动重试，说明实际阻断，不绕过 |
| 链接失效/仅笔记未带商品 | 请从小红书商品详情重新分享完整商品链接 |
| 文本读到商品但某字段缺失 | 先展示已取得字段，按上文预算补证；仍缺时只补当前字段，不要求全部重填 |
| 仅24h加购缺失 | 正常桌面边界，继续其他字段；完整评分前可补一次手机端数据，无数据则给阶段结果 |

用户明确不掌握数据时停止追问该项，不要求商家后台权限，不据此说“插件坏了”。普通输出保持简洁；用户要求排障时，列实际工具名、是否缓存、关键原文和失败状态，以便区分没抓到与没展示，不暴露Cookie/令牌。未安装对应搜索能力时，对标记为“尚未验证”，不能当作“没有符合条件的对标”而淘汰。
