# WorkBuddy 读不到小红书商品数据：操作指引

适用：爆不爆公开商品页的名称、规格、展示价、单品累计销量读取。24小时加购在电脑端不可取得，留空是正常边界。站内对标搜索需要另行核实相应连接器及登录状态。

## 先更新并做一次最小检查

1. 在 WorkBuddy 头像菜单点“检查更新”。本次验收版本为5.8.3；其他版本以实际界面和可用工具为准。
2. 安装本仓库正式发布包，确认爆不爆技能启用。新建一个普通任务，避免旧任务沿用旧规则。让它读取技能目录的 `VERSION` 文件确认实际安装版本。
3. 发下面的话，再附上从小红书商品详情分享的完整链接：

> 用爆不爆读取这个商品的名称、规格、当前展示价和单品累计销量，24小时加购暂时不提供。请真实调用当前可用的网页获取工具；若失败，告诉我实际工具名和错误原因，不要只说数据不足。

4. 展开任务中的工具执行过程，核对是否真的调用“网页获取”（本次版本工具名 `WebFetch`），以及实际返回的原文/错误。模型一句“没有工具”不等于已检查工具清单；没有调用记录时不能声称抓取失败。

## 三种能力不要混淆

| 名称 | 做什么 | 这次商品基础字段测试是否依赖 |
|---|---|---|
| 网页获取 / WebFetch | 按URL读取网页内容，结果回到任务中 | 是 |
| 内置浏览器 | 在 WorkBuddy 里展示和查看网页 | 未依赖手动打开 |
| 浏览器操控、Chrome/Edge扩展 | 连接并操作外部浏览器 | 未调用 |

2026-10-21本机设置中，“通用 → 链接打开方式”为“智能打开”，“智能体 → 让 WorkBuddy 控制浏览器”显示“安装”，外部浏览器扩展状态为“无法确认安装状态”；在此状态下，公开商品页已通过网页获取成功读取。安全中心网络规则为空，未发现给小红书增加的特定放行规则。不能据此保证每台学员机器一致，但没有证据支持“必须先装浏览器扩展或买接口”才能读公开商品页。

“通用 → 链接打开方式”调整的是对话里链接的打开策略，不是已证实的 WebFetch 启用开关。本机界面未发现单独的“开启网页获取”开关；不要虚构菜单路径。

## 按实际现象处理

| 实际现象 | 操作 |
|---|---|
| 技能没有加载 / 仍使用旧规则 | 核对技能启用、`VERSION`，新建普通任务后再试 |
| 出现访问网站的权限确认 | 核对目标确为本次小红书商品链接及正常跳转，再允许这次只读访问；保留“默认权限”即可 |
| 明确显示网络规则拦截 | 头像 → 设置 → 安全中心 → 网络安全，检查命中的具体域名/URL规则及审批记录；只处理实际阻断，不一键放开全部权限或关闭沙箱 |
| 明确没有可用网页获取工具 | 核对客户端版本、普通任务/受限工作区状态和实际工具清单；保存报错给助教。不要先假定是浏览器扩展缺失 |
| 返回未登录、验证码、访问受限 | 按实际工具提示完成它所使用会话的正常登录/人工验证；外部浏览器登录不会自动传给网页获取。遇到访问受限停止反复重试 |
| 链接失效或只读到笔记 | 从商品详情重新分享完整商品链接，不用猜测ID拼接网址 |
| 已取得商品但缺个别字段 | 先展示已取得内容；最多一次针对性补证，仍缺则留空或只补该字段 |
| 仅24小时加购缺失 | 正常，继续其他字段；不要求商家后台或重复抓取 |

如需反馈，提供 WorkBuddy 版本、系统、模型、爆不爆版本，以及该任务“网页获取”的展开结果；隐藏Cookie、令牌与账号隐私。不要只截最终“数据不足”一句。

## 依据与边界

- 本机实际界面与调用日志：2026-10-21，WorkBuddy 5.8.3 / Deepseek-V4.1-Flash / 默认权限。
- [官方系统设置说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)：头像设置入口、检查更新与设置分组。
- [官方默认权限与安全沙箱说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Permission-Modes)：默认权限支持受控网络访问，安全中心配置网络规则；受限工作区可能限制技能/工具加载。
- 学员原机器的具体原因需原任务工具记录确认；本机成功不等于学员现场已恢复。
